# Open-ended weekly maintenance design

A reviewed weekly rule can run until canceled. Save its local first start and end, timezone, interval and fold choices, and show the exact UTC intervals for the initial batch. A rule retains the original review. Each generated window records its own original local and UTC interval and the timezone database version used to generate it. Once materialized, its UTC interval is fixed and can be edited or canceled as a one-date exception.

Persist the next occurrence number, previous resolved end and refill time independently of the materialized windows. Review eight dates initially and keep a bounded reserve of upcoming schedule slots. Refill under the existing exclusive maintenance lock, one series per transaction. Refill is idempotent and does not overwrite child exceptions. After downtime, use arithmetic on civil dates to find the small range that can still be active or upcoming. Safely elapsed slots that were never materialized are skipped, including civil-time errors wholly within that elapsed range. They do not create retroactive notification holds. Catch up before notification workers start and refill periodically during operation.

Resolve each later date using the same civil-time rules as a finite schedule. If a later endpoint cannot be resolved, or the base intervals would overlap, keep all previously saved dates and stop generation at the affected index with a visible reason. The operator can cancel the rule and create a reviewed replacement. An open-ended series cannot edit its underlying rule in place.

Cancel future generation and all materialized windows that have not started in one transaction. A cancellation can be reviewed with zero upcoming windows. The review carries the series revision and a digest of the exact set of upcoming window IDs and revisions. A new upcoming date or a date starting before apply requires re-review. The active window keeps its separate end action.

Keep the parent and original review while the rule can still generate or while a generation issue needs attention. Apply the existing 30-day, reference-aware retention to untouched ended children. Keep manually changed exceptions with their audit while the rule remains open. After stopping the rule, its parent and remaining children use the existing terminal-series retention rules. Page the persisted windows and events without reading the entire series.
